It is not a final `v3.0.0` release: a human creator still needs to review the dashboard in the real authoring workflow, and the dirty worktrees prevent creating a tag that would honestly point at exactly this source state.

## Release blockers

1. Human creator visual review at desktop `1440x900` and mobile `390x844` must be recorded before final release.
2. The source worktrees contain pre-existing and current uncommitted changes. Do not create `v3.0.0-rc1` against an older HEAD; create the tag only after a deliberate release commit or an explicitly approved release branch.
3. Workspace-level Wucheng validation reports 21 missing declared media. The projection reports 25 sentinels because it also includes invalid/mismatched declarations; neither count is hidden.
4. Workspace scan cannot prove absence of consumers outside `D:\study\Software`; the clean break must be called out in release notes.
5. The Python Core is clean-break, but the bundled skill's standalone v1.x artifact-validator surface remains a separately scoped migration item; it is not imported by the Core package, but it is still present in the skill archive.

The release archive no longer carries the old `filmfoundry-v2*.md` active document names or project-specific Wucheng command paths. This removes an active navigation ambiguity but does not remove the standalone validator/template migration blocker listed above.
