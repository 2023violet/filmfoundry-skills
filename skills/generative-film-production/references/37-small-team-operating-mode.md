# 37 - Small Team Operating Mode

## Goal

Small teams need the same authority boundaries with fewer handoffs. Keep one
owner for the Canon and Shot Spec, one current runtime record, and only the
visual controls that remove a real production risk.

## Minimum operating set

For a low-risk one-off:

- Shot Spec;
- Asset Passport only for recurring assets;
- one selected reference or no visual-control artifact;
- one QC decision before generation.

For a recurring character or location:

- Asset Passport and registry identity;
- Character or Location Reference;
- Spatial Map when screen geography carries the edit;
- observed state written after the Select.

For a high-risk state or motion transition:

- Visual Control Plan;
- state-matched authority frame or Previsualization;
- Scale Reference or Physics Cue when that fact carries the story;
- provider capability evidence and human review.

## Three-person role bundle

One person may hold several roles, but keep the responsibilities visible:

- **Story/Canon:** owns narrative facts, Shot Specs, and state intent.
- **Control/QC:** owns references, maps, scale/physics cues, and alignment
  review.
- **Route/Edit:** owns provider route selection, Selects, observed state, and
  edit coverage.

Use stable IDs and shared templates so a handoff is a file review rather than
an oral memory transfer. A short review of the current control plan is cheaper
than rebuilding an episode after identity, geography, or timing drift.

## Stop rules

Stop and repair upstream when identity, state alignment, camera side, location
anchors, or the required physical result fails. Before a retry, check whether a
contiguous partial Select already satisfies the edit target. If a retry is
needed, change one variable tied to the recorded failure.

Do not scale a small-team workflow by generating every possible view,
expression, previs panel, or model test. Scale the evidence and controls with
the current approved production scope.
